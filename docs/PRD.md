# PRD: 모두AI — 처음 만나는 AI 활용 코스웨어

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 제품명 | 모두AI `확정` (영문 표기·도메인은 미정) |
| 버전 | v0.1 (MVP) |
| 작성일 | 2026-10-16 |
| 문서 상태 | 개발 착수 가능 / 출시 전 결정 5건 남음 (14절) |
| 한 문장 정의 | AI를 처음 접하는 초등 저학년부터 시니어까지 4개 수준 학습자가 강사 수업이나 혼자 학습으로 AI를 이해하고, 질문하고, 답을 확인하는 법을 익히는 반응형 웹 코스웨어 |

상태 표시: `확정` 인터뷰에서 결정, `제안` 작성자 제안(검토 필요), `가정` 확인 전 임시 기준, `미정` 결정 필요.

## 2. 문제와 목표

### 현재 불편
- AI 활용 교육 자료가 성인 기준으로 만들어져 초등 저학년·시니어에게 맞지 않는다.
- 학교 수업, 교사 연수, 복지관 강좌가 각자 자료를 따로 만들어 쓴다.
- 아동이 실제 AI 서비스를 쓰기엔 연령 제한과 개인정보 문제가 있다.
- 사용법 위주 교육이 많고, AI 답을 확인하는 법은 거의 다루지 않는다.

### 해결할 일
- 같은 단원 구조를 4개 수준에 맞춰 제공해 강사가 대상만 고르면 바로 수업할 수 있게 한다.
- 초등은 안전한 연습 AI, 중고생 이상은 실제 AI로 실습한다.
- 학습자 개인정보를 거의 받지 않고도 강사가 수업 진도를 볼 수 있게 한다.

### 성공 지표 (제안)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 단원 완료율 | 강사 수업 모드에서 참여 학습자의 80% 이상이 해당 차시 마지막 단계 도달 | progress 테이블 집계 |
| 확인 퀴즈 정답률 | 수준별 평균 70% 이상 | 퀴즈 결과 집계 |
| 입장 소요 시간 | 수업 코드 입력부터 1단계 화면까지 시니어 기준 1분 이내 | 시범 수업 관찰 |
| 수업 중단 | API 장애로 수업이 멈춘 사례 0건 | 대체 모드 전환 로그 |
| 시범 운영 | 4개 수준 각 1회 이상 시범 수업 | 운영 기록 |

## 3. 대상과 사용 상황

### 학습 수준 `확정`

| 코드 | 수준 | AI 실습 방식 | 비고 |
|---|---|---|---|
| L1 | 초등 1~2학년 | 연습 AI (미리 만든 질문·답) | 글 읽기 부담 큼, 강사·보호자 도움 전제 |
| L2 | 초등 3~6학년 | 연습 AI (선택형 질문 조립) | 자유 입력 없음 |
| L3 | 중고생·성인 | 실제 AI (자유 입력) | 중학생 일부는 만 14세 미만 |
| L4 | 시니어 | 실제 AI (자유 입력, 음성 입력 권장) | 큰 글씨, 단순한 화면 |

### 사용자 역할

| 역할 | 설명 | 로그인 |
|---|---|---|
| 운영자 | 서비스 관리, AI 공급자·모델·사용량 상한 설정 | Google 로그인 + 운영자 권한 |
| 강사 | 수업 개설, 수업 코드 발급, 진도 확인 (교사, 연수 강사, 복지관 강사) | Google 로그인 |
| 수업 참여 학습자 | 수업 코드 + 별명으로 입장 | 없음 (익명 세션) |
| 혼자 학습자 | 수준 선택 후 바로 학습 | 없음 (익명 세션, 진도는 기기 저장) |

### 대표 시나리오
1. **초등 3학년 수업:** 교사가 L2 · 3단원 수업을 열고 칠판에 코드 6자리를 띄운다. 학생은 태블릿으로 코드와 별명을 넣고 입장한다. 교사는 화면에서 누가 어느 단계에 있는지 보며 수업을 진행한다.
2. **복지관 시니어 강좌:** 강사가 L4 · 1단원 수업을 연다. 어르신은 휴대폰으로 큰 숫자 키패드에 코드를 입력한다. "해 보기" 단계에서 마이크 버튼을 눌러 "손주 생일 선물 추천해 줘"라고 말하고 AI 답을 본다.
3. **혼자 학습:** 직장인이 링크로 들어와 L3을 고르고 출퇴근길에 2단원을 절반 하다 닫는다. 다음 날 같은 휴대폰으로 들어오면 이어서 시작한다.
4. **API 장애:** 수업 중 AI 공급자 응답이 끊긴다. 학습자 화면은 "지금은 연습 모드예요"로 바뀌고 예시 답변으로 활동을 이어 간다. 강사 화면에는 원인 안내가 뜬다.

## 4. 범위와 우선순위

### 단원 구성 `확정`
6개 공통 단원 × 4개 수준. 1단원 = 1차시(40~60분). 각 단원은 5단계: 열기 → 알아보기 → 해 보기 → 확인 퀴즈 → 정리 (단계당 5~10분).

| 단원 | L1 초등 1~2 | L2 초등 3~6 | L3 중고생·성인 | L4 시니어 |
|---|---|---|---|---|
| 1. AI를 만나요 | 사람·AI·기계 구분 놀이 | AI가 배우는 방법(데이터·패턴) 체험 | 생성형 AI 원리, 할 수 있는 일과 못 하는 일 | 생활 속 AI 찾기(음성비서, 번역, 길찾기) |
| 2. AI에게 말 걸기 | 그림 카드로 부탁하기 | 좋은 질문과 아쉬운 질문 비교 | 프롬프트 구조(역할·조건·형식) | 말로 묻기, 쉬운 질문 만들기 |
| 3. AI 답 확인하기 | "정말일까?" 맞다·틀리다 고르기 | 틀린 답 찾기, 출처 확인 | 환각 검증, 교차 확인 | 그럴듯한 거짓말 구별하기 |
| 4. 안전하게 쓰기 | 내 이름·주소 말하지 않기 | 개인정보, 저작권 기초 | 개인정보·저작권·윤리, 과제 정직성 | 딥페이크·보이스피싱·가짜뉴스 사기 예방 |
| 5. 생활에 쓰기 | AI랑 이야기 만들기 | 학습 도우미로 쓰기(요약, 퀴즈) | 공부·업무 활용(요약, 글쓰기, 정리) | 문자 쓰기, 병원·민원 정보 찾기 |
| 6. AI로 만들어 보기 | 그림·이야기 만들기 | 나만의 퀴즈·발표 자료 | 작은 자동화·결과물 제작 | 손주에게 보낼 카드·여행 계획 |

### MVP 포함 `확정`
- 4개 수준 × 1~3단원 = 12차시 콘텐츠
- 강사 수업 모드, 혼자 학습 모드
- 연습 AI(L1·L2), 실제 AI(L3·L4), API 실패 시 3단계 대체
- 강사 대시보드(수업 개설, 코드 발급, 실시간 진도)
- 운영자 AI 설정(공급자·모델 교체, 사용량 상한)
- 음성 입력, 글자 크기 조절
- PC·태블릿·모바일 반응형

### MVP 제외 (후속)
- 4~6단원 콘텐츠 (2차)
- 음성 안내(읽어 주기) — 이번에는 넣지 않음 `확정`
- 학습자 간 여러 AI 답 비교 활동 — 운영자 전환만 지원 `확정`
- 혼자 학습 기기 간 이어하기 코드
- 콘텐츠 편집 관리자 화면 (MVP는 코드 저장소의 JSON 파일로 관리)
- 수료증, 강사용 지도안 다운로드
- 다국어

범위를 나눈 이유: 4개 수준을 모두 넣어야 저학년·시니어 화면 문제를 초기에 발견할 수 있고, 1~3단원이 이해 → 질문 → 검증으로 이어져 짧은 과정으로 완결된다.

## 5. 사용자 흐름

### 5.1 강사 수업 모드
1. 강사가 Google로 로그인한다.
2. "새 수업"에서 수준(L1~L4)과 단원을 고른다. 수업 이름은 선택 입력.
3. 서버가 6자리 숫자 수업 코드를 만든다. 화면에 큰 글씨 코드와 QR을 띄운다.
4. 학습자가 첫 화면에서 "수업 코드로 들어가기" → 코드 입력 → 별명 입력 → 입장.
5. 강사 대시보드에 입장한 별명이 나타나고, 단계별 진행 상황이 실시간으로 갱신된다.
6. 강사는 "모두 같은 단계로 이동" 또는 "각자 진행" 중 하나로 수업을 운영한다.
7. 수업 종료를 누르면 새 입장이 막히고, 학습자 화면에 정리 단계와 종료 안내가 뜬다.

### 5.2 혼자 학습 모드
1. 첫 화면에서 "혼자 배우기" → 수준 선택(그림과 설명이 있는 큰 카드 4개).
2. 단원 목록에서 단원 선택 → 5단계 진행.
3. 단계를 마칠 때마다 진도를 기기에 저장한다. 다시 들어오면 "이어서 하기" 버튼을 먼저 보여 준다.
4. L3·L4의 실제 AI 실습은 화면에 들어올 때 서버가 익명 세션을 만들어 사용량을 제한한다.

### 5.3 AI 실습 흐름 (L3·L4)
1. 학습자가 글자나 음성으로 질문을 입력한다.
2. 서버가 입력을 검사한다. 전화번호·주민등록번호·이메일·계좌번호 형태가 있으면 전송하지 않고 "개인정보가 들어 있어요. 지우고 다시 보내 주세요"를 띄운다.
3. 서버가 수준별 지침(시스템 프롬프트)과 함께 AI에 보낸다.
4. 답을 받아 출력 검사를 거쳐 화면에 보여 준다. 답 아래에 "AI 답은 틀릴 수 있어요" 표시를 항상 붙인다.

### 5.4 API를 쓸 수 없을 때 `확정`

| 순서 | 조건 | 동작 |
|---|---|---|
| 1 | 상위 모델 오류·시간 초과(15초, 제안) | 같은 공급자의 경량 모델로 재시도 |
| 2 | 경량 모델도 실패 | 운영자가 등록한 예비 공급자로 자동 전환 |
| 3 | 모든 공급자 실패, 사용량 상한 도달, API 키 미등록, 네트워크 차단 | 그 활동을 연습 AI 모드로 전환. 학습자 화면 상단에 "지금은 연습 모드예요" 띠 표시 |
| 강사 안내 | 3번 발생 시 | 강사 대시보드에 원인(장애/상한/미설정)과 대처 문구 표시 |
| 복구 | 다음 질문 시점 | 1번부터 다시 시도. 성공하면 연습 모드 표시 제거 |

- 무료 등급 API는 대체 순서에 넣지 않는다 `확정`. 무료 등급은 입력과 답을 공급자의 제품 개선에 쓰고 사람이 검토할 수 있기 때문이다.
- 예비 공급자 자동 전환은 운영자가 "자동 전환 허용"을 켠 경우에만 동작한다 `제안`.

### 5.5 실패·예외 흐름

| 상황 | 처리 |
|---|---|
| 없는 수업 코드 | "코드를 다시 확인해 주세요" + 입력값 유지 |
| 종료된 수업 코드 | "이 수업은 끝났어요. 선생님께 새 코드를 받아 주세요" |
| 같은 수업에 같은 별명 | "이미 쓰는 이름이에요" + 뒤에 숫자 붙인 이름 추천 |
| 코드 5회 연속 오류 | 1분간 입력 잠금 (무작위 대입 방지) |
| 음성 입력 미지원 브라우저 | 마이크 버튼은 보이되 누르면 "이 기기에서는 말로 입력할 수 없어요. 글자로 써 주세요" |
| 마이크 권한 거부 | 권한 허용 방법을 그림으로 안내, 글자 입력으로 유도 |
| 기기 저장 불가(사생활 보호 모드 등) | 학습은 그대로 진행, "이 기기에는 진도가 저장되지 않아요" 1회 안내 |
| 인터넷 끊김 | 현재 단계 화면 유지, 진도 전송은 재연결 후 다시 시도 |

## 6. 화면·UX 요구사항

### 공통 원칙
- 한 화면에 할 일은 하나. 다음 행동 버튼은 항상 화면 아래쪽 같은 자리에 둔다.
- 기기 대응: 가로 360px 휴대폰부터 데스크톱까지. 특정 기기 전용 제스처(스와이프만으로 이동 등)를 쓰지 않는다.
- 터치 영역: 최소 48×48px, L4는 56×56px.
- 기본 글자 크기: L1·L4 20px, L2 18px, L3 16px. 모든 화면에 글자 크기 3단계 조절 버튼.
- 색 대비 WCAG 2.1 AA 이상. 색만으로 정답·오답을 구분하지 않는다(아이콘·글자 함께).
- 음성 안내는 없음. L1은 그림·아이콘 비중을 높이고 문장을 짧게 쓴다.
- 문구는 쉬운 말, 존댓말(L1·L2는 친근한 해요체).

### 콘텐츠 문구 기준 `확정: 글은 적게, AI문체 금지`

화면 하나에 읽을 글이 많으면 처음 AI를 접하는 학습자는 바로 손을 놓는다. 설명은 짧게 쓰고 나머지는 그림, 예시, 직접 해 보기로 채운다.

**수준별 글 분량 상한** `제안`

| 수준 | 한 화면 문장 수 | 한 문장 길이 | 설명 카드 한 장 | 그 밖에 |
|---|---|---|---|---|
| L1 | 2문장 | 20자 이내 | 40자 | 모든 문장에 그림 짝. 어려운 낱말 금지 |
| L2 | 3문장 | 30자 이내 | 80자 | 새 낱말은 한 화면에 하나만 |
| L3 | 5문장 | 50자 이내 | 150자 | 더 읽을 내용은 "더 보기"로 접기 |
| L4 | 3문장 | 30자 이내 | 80자 | 외래어는 우리말로 (프롬프트 → 질문, 업로드 → 올리기) |

**쓰지 않는 표현 (AI문체)**

| 패턴 | 피할 예 | 이렇게 |
|---|---|---|
| 번역투 | ~를 통해, ~에 있어서, ~에 의해 만들어진 | AI로, AI가 만든 |
| 피동·명사화 | 활용이 가능합니다, 확인이 필요합니다 | 써 볼 수 있어요, 확인해 봐요 |
| "~하는 것이 중요합니다" | 출처를 확인하는 것이 중요합니다 | 출처를 꼭 확인해요 |
| 대조 프레이밍 | AI는 마법이 아닙니다. 도구입니다 | AI도 틀릴 때가 있어요 |
| 자문자답 | AI는 어떻게 배울까요? 바로 데이터입니다 | AI는 많은 글을 보고 배워요 |
| 예고문 | 지금부터 알아보겠습니다 | (지우고 바로 본론) |
| 교훈형 마무리 | 꾸준히 실천해 보세요, 도움이 되었길 바랍니다 | 배운 것 한 줄 + 다음 단원 버튼 |
| 막연한 유행어 | 여정, 생태계, 인사이트, 혁신적인 | 구체적인 말로 바꾸거나 지움 |
| 기계적인 세 가지 나열 | 빠르고, 정확하고, 편리한 | 꼭 필요한 하나만 |
| 상투어·강조 남발 | 한마디로, 핵심은, 바로 | 지움 |
| 첫머리 칭찬 | 훌륭한 질문이에요! | 답부터 |
| 볼드·이모지·콜론·대시 남용 | **중요!** ✨ — | 강조는 한 화면에 한 번까지 |

**쓰는 법**
- 학습자에게 말 걸듯 쓴다. L1·L2·L4는 해요체, L3는 해요체 또는 합니다체 중 하나로 통일.
- 예시는 학습자 생활에서 가져온다 (L1 간식·놀이, L2 숙제·발표, L3 과제·업무 메일, L4 문자·병원·손주).
- 문장 길이를 일부러 섞는다. 짧은 말로 끊고, 필요한 곳에서만 길게.
- AI로 문안 초안을 만들었다면 이 표로 다시 고친 뒤 넣는다.

**실제 AI 답변 (L3·L4)도 같은 기준을 따른다.** 시스템 프롬프트에 분량(L3 기본 5문장, L4 기본 3문장)과 위 금지 표현을 넣는다. 학습자가 "자세히"를 요청하면 늘려도 된다.

## 8. 데이터 모델

콘텐츠는 DB가 아닌 저장소의 JSON 파일로 관리한다 `제안`. 경로 예: `content/L2/unit-03.json`.

### 콘텐츠 JSON 구조 (요약)
```json
{
  "level": "L2",
  "unit": 3,
  "title": "AI 답 확인하기",
  "steps": [
    { "type": "intro", "body": "...", "image": "..." },
    { "type": "explain", "cards": [ { "title": "...", "body": "..." } ] },
    { "type": "practice", "mode": "blocks", "blocks": [...], "answers": { "조합키": "미리 만든 답" } },
    { "type": "quiz", "items": [ { "q": "...", "choices": [...], "answer": 1, "explain": "..." } ] },
    { "type": "wrap", "points": ["...", "..."] }
  ],
  "fallbackAnswers": { "기본": "연습 모드 예시 답" }
}
```
L3·L4의 `practice` 단계도 `fallbackAnswers`를 반드시 가진다.

### DB 테이블 (Supabase)

| 테이블 | 주요 필드 | 소유자 | 민감도 | 보관·삭제 |
|---|---|---|---|---|
| profiles | id(uuid, auth.users 참조), display_name(text), role(enum: teacher, admin), created_at | 본인 | 낮음 (이메일은 Supabase Auth에만) | 탈퇴 시 삭제 |
| classes | id, teacher_id(fk), level(enum L1~L4), unit(int 1~6), title(text, 선택), code(char6), pace_mode(enum: sync, free), current_step(int), status(enum: open, closed), expires_at, created_at | 강사 | 낮음 | 종료 후 90일 뒤 삭제 (제안) |
| class_participants | id, class_id(fk), anon_user_id(uuid), nickname(text 1~10자), joined_at | 수업 강사가 조회 | 낮음 (별명만) | 수업 삭제 시 함께 삭제 |
| progress | id, participant_id(fk), step(int 1~5), completed_at, quiz_score(int, 선택) | 학습자 본인 쓰기, 강사 읽기 | 낮음 | 수업 삭제 시 함께 삭제 |
| ai_usage | id, class_id(nullable), anon_user_id, provider, model, fallback_level(int 0~3), created_at | 서버만 쓰기 | 낮음 (대화 내용 없음) | 90일 뒤 삭제 (제안) |
| ai_settings | id, provider_order(jsonb), auto_failover(bool), class_limit(int), session_limit(int), updated_by, updated_at | 운영자 | 낮음 (키 값은 저장 안 함) | 유지 |

- **AI 대화 내용은 저장하지 않는다** `제안`. 사용 횟수와 대체 단계만 기록한다.
- 코드 중복 방지: `classes.code`에 `status = 'open'` 조건부 유니크 인덱스.
- 혼자 학습 진도는 브라우저 저장소에만 있고 서버로 보내지 않는다.

## 9. 연동과 AI

| 서비스 | 역할 | 비고 |
|---|---|---|
| Supabase Auth | 강사 Google 로그인, 학습자 익명 세션 | 익명 세션으로 RLS 적용 |
| Supabase DB + Realtime | 수업·진도 저장, 강사 화면 실시간 갱신 | |
| Vercel | Next.js 배포, 서버 함수 | 환경변수에 API 키 보관 |
| Gemini API (유료 등급) | 기본 AI 공급자 `확정` | 유료 등급은 입력·답을 제품 개선에 쓰지 않음 |
| 그 밖의 AI API (OpenAI, Claude 등) | 운영자가 교체·예비로 등록 `확정` | 공급자별 데이터 조건을 등록 전에 확인 |
| 브라우저 음성 인식 (Web Speech API) | 음성 입력 | 브라우저별 지원·처리 방식 차이 있음 (10절) |

### AI 호출 계약
- 엔드포인트: `POST /api/ai/chat` (서버 전용)
- 입력: `{ level: "L3"|"L4", unit: number, message: string(1~500자) }` + 세션 토큰
- 서버 처리 순서: 세션 확인 → 사용량 상한 확인 → 개인정보 검사 → 공급자 호출(5.4절 순서) → 출력 검사 → 사용량 기록
- 출력: `{ answer: string, mode: "live"|"practice", notice?: string }`
- 시간 초과: 공급자별 15초 (제안), 전체 40초 넘으면 연습 모드 전환
- 공급자 차이는 서버의 공급자 어댑터 한 곳에서만 처리한다. 화면 코드는 공급자를 모른다.

### 수준별 시스템 프롬프트 원칙
- L3: 정확하게 답하고, 모르면 모른다고 말하며, 확인이 필요한 정보는 확인 방법을 함께 안내.
- L4: 짧은 문장, 쉬운 말, 금융·의료·법률 결정은 전문 기관 확인 권유, 송금·개인정보 요구에는 사기 주의 안내.
- 공통: 개인정보를 묻지 않음, 학습 단원 주제 밖 요청은 짧게 답하고 단원 활동으로 되돌림.

### 요구사항
- 모든 권한은 Supabase RLS와 서버 함수에서 강제한다. 화면에서 버튼을 숨기는 것만으로 처리하지 않는다.
- RLS 예: `classes`는 `teacher_id = auth.uid()`인 행만 조회·수정. `progress`는 `participant.anon_user_id = auth.uid()`만 쓰기, 해당 수업 강사만 읽기.
- 서버 전용 키(service role)는 서버 함수에서만 쓰고 브라우저 번들에 넣지 않는다.
- AI API 키는 Vercel 환경변수에만 두고 DB·로그·브라우저에 남기지 않는다.
- 입력 검증은 서버에서 다시 한다(코드 6자리 숫자, 별명 길이·금칙어, 메시지 길이).
- 학습자 개인정보 수집 최소화: 별명 외 수집 없음. 별명 입력란에 "실제 이름 대신 별명을 써요" 안내.
- 만 14세 미만 학습자: 실명·연락처를 받지 않고 대화 내용도 저장하지 않는 구조로 설계한다. 다만 L3에 중학생이 포함되므로 법정대리인 동의 필요 여부를 출시 전 확인한다 (14절).
- 민감한 원문을 저장하지 않으므로 필드 암호화 대상은 MVP에 없다. 이후 대화 저장 기능을 넣으면 신뢰 계층에서 필드 암호화를 적용하고 키는 데이터와 분리 보관한다.
- 로그: 학습자 입력·AI 답 원문을 서버 로그에 남기지 않는다. 오류 로그에는 요청 ID와 오류 코드만 기록한다.
- 음성 입력: 일부 브라우저는 음성을 제조사 서버로 보내 글자로 바꾼다. 첫 사용 시 "말한 내용이 글자로 바뀌는 과정에서 브라우저 회사 서버를 거칠 수 있어요" 안내를 1회 보여 준다.
- 전송 구간은 HTTPS만 허용.
- 백업: Supabase 기본 백업 범위를 따른다. 삭제 요청 시 백업 보관 기간 내 잔존 가능성을 개인정보처리방침에 적는다.

### SQL 파일 규칙
후속 개발에서 만드는 SQL은 `supabase/migrations/` 폴더에 순서 번호를 붙여 모은다.
예: `001_create_profiles.sql`, `002_create_classes.sql`, `003_rls_policies.sql`

1. **뼈대:** 프로젝트 생성, 반응형 레이아웃, 글자 크기 조절, 첫 화면·수준 선택 (FR-019 / AC-027)

## 14. 결정·가정·미결정·위험

### 확정된 결정

| 결정 | 근거 |
|---|---|
| 강사 진행 + 혼자 학습 두 모드 | 저학년·시니어는 강사 도움 필요, 혼자 학습 수요도 있음 |
| 초등은 연습 AI, L3·L4는 실제 AI | 아동 연령 제한·안전, 성인은 실전 경험 필요 |
| 6개 공통 단원 × 4개 수준, 1단원 = 1차시 5단계 | 화면 틀 재사용, 수업 시간에 맞춤 |
| 강사만 로그인, 학습자는 코드 + 별명 | 개인정보 최소화, 입장 장벽 최소화 |
| Gemini 유료 등급 기본, 다른 AI는 운영자 교체 | 데이터 조건, 장애 대비 |
| Next.js + Supabase + Vercel | 서버 측 키 보관, RLS로 데이터 분리 |
| 음성 안내 없음, 음성 입력 있음 | 사용자 결정 |
| 제품명 모두AI | 사용자 결정 |
| 글은 적게, AI문체 금지 (6절 기준) | 처음 AI를 접하는 학습자의 읽기 부담 |
| MVP = 4개 수준 × 1~3단원 | 수준별 문제 조기 발견 |
| API 실패 시 3단계 대체, 무료 등급 제외 | 수업 중단 방지, 학습자 입력 보호 |

### 가정
- 수업당 학습자 35명 이하.
- 수업 코드 유효시간 24시간.
- 콘텐츠(12차시 문안·퀴즈·연습 답변)는 기획자가 작성·검수한다. AI로 초안을 만들더라도 사람이 검수한 뒤 JSON에 넣는다.
- AI 대화 내용은 저장하지 않는다.
